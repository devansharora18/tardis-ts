# Packaging native binaries

Tardis ships the Rust sources and prebuilt runtime packages.

## npm layout

- `@devansharora18/tardis-ts` — CLI, compiler, JS runtime, Rust sources.
- `@devansharora18/tardis-ts-<platform>-<arch>` — one native binary per target:
  `linux-x64`, `linux-arm64`, `darwin-x64`, `darwin-arm64`, `win32-x64`.
Windows arm64 is not published yet.

The CLI looks for, in order:

1. `TARDIS_TS_NATIVE_BIN`
2. `node_modules/@devansharora18/tardis-ts-<platform>-<arch>/bin/tardis-ts-native`
3. `native/target/{release,debug}/tardis-ts-native` in the app or package
4. `node_modules/.bin/tardis-ts-native`
5. `dist/bin/tardis-ts-native`

If none exists, `tardis-ts run` prints the source-build command.

## Cutting a release

1. Set the version in `package.json`.
2. Commit, then tag: `git tag v2.0.0-alpha.1 && git push origin main --tags`.
3. The `release` workflow builds each target, signs when secrets exist,
   assembles platform packages, and publishes all packages to npm.
4. Verify: `npm view @devansharora18/tardis-ts version` and install in a clean
   directory; `npx tardis-ts screenshot` should not need Rust.

Platform packages are generated by `scripts/package-native.mjs`; the root
manifest receives `optionalDependencies` from
`scripts/inject-optional-deps.mjs` at publish time only, so local development
never waits on unpublished packages.

## Signing secrets

macOS:

- `MACOS_CERTIFICATE` — base64 of the Developer ID Application `.p12`.
- `MACOS_CERTIFICATE_PASSWORD`
- `MACOS_SIGN_IDENTITY` — e.g. `Developer ID Application: Name (TEAMID)`.
- `APPLE_ID`, `APPLE_TEAM_ID`, `APPLE_APP_PASSWORD` — notarization.

Windows:

- `WINDOWS_CERTIFICATE` — base64 of the code-signing `.pfx`.
- `WINDOWS_CERTIFICATE_PASSWORD`.

Without secrets the workflow still publishes unsigned binaries. Gatekeeper and
SmartScreen will warn until the certificates are configured.

## Local platform package

```sh
node scripts/package-native.mjs \
  --platform linux --arch x64 \
  --binary native/target/release/tardis-ts-native \
  --version 2.0.0-alpha.0 --out platform-dist
```

`release.yml` uses the same script. Arm64 Linux runners and the Intel macOS
runner are part of the matrix.
